# 试用故障复盘与验收

调度可靠性、agent 的业务判断和业务系统验收是三个不同层次；某一层通过不能替代其他层。

| 卡点 | 影响 | 处理与验收边界 |
| --- | --- | --- |
| 回执写失败、心跳过期 | 假执行中或待核对 | 有界重试、恢复写队列；没有终止证据不能重放业务 |
| CLI 已退出，后代继承输出管道 | 等待 close 导致结果不落盘 | exit/close 分离；真实进程夹具验证，不杀后代服务 |
| 长结果截断、格式不合约 | 错误待验收或反复修复 | 长尾契约、字段诊断、每轮一次格式修复；矛盾输出拒绝 |
| 一轮结束与需求完成混淆 | 本可继续却要求用户介入 | complete/continue/blocked/decision 分开；限制无进展续办 |
| 没有明确恢复事件、时间或游标 | 回复后不继续或重复执行 | 带时区时间、可信作者、父子关系、持久游标；过期只观察，不增加权限 |
| 排队续办过期后 attempts 为空 | 原会话存在却无法恢复 | 仅恢复匹配 durable session 的已确认历史 attempt，保留旧截止 |
| 持续监听失败只有详情页错误 | 用户不知道自动推进已失效 | 三次连续失败全局提示并回写一次，恢复回写一次；重启不刷屏，不上传异常原文 |
| 真实业务 SQL 超时 | 发布正式质量门失败 | 独立诊断、语义等价修复和真实发布验收；缓存命中、基础 health、隔离小数据不能替代 |
| 协调者推进判断失误 | 重复问授权、将无关测试当发布门、本地修复被外部等待阻塞 | 以真实入口判定必需检查；区分 owner 已授权与 peer 就绪；主动推进独立可做事项 |

后两类不能由调度内核自动证明正确。模型必须核对实际证据，不能靠更多提示词或状态改名宣称完成。

## 可重复验收

`npm test` 注入重启、丢失回写响应、并发轮询、过期、接管、长输出、继承管道和会话恢复故障。它证明状态机行为，不冒充真实跨机器验收。

`scripts/native-acceptance.js` 是 opt-in 的真实原生 host 验收协调器，通过已认证面板操作；任务由真实 Linear 轮询进入，不写伪造的 task/attempt/result。运行前要求原任务均已结束，临时关闭其他项目 intake/followup，备份配置并验证原任务状态和 attempt 列表未变。

- `file`：官方 Codex 两轮实际文件写入/读回，缺失 executable 验证明确拒绝后的 fallback。
- `repair`：原生 DSH 一次格式修复、定时等待、原会话续接。
- `timer`：Claude Code 定时原会话续接。
- 完成后核对真实 Linear In Review 和回写 ID，再等一轮轮询检查无重复执行；恢复配置并保持暂停。
- `peer`：独立协作者真实身份回复。owner 自己发同样标记是负向对照，不能唤醒；监听建立后保留隔离配置等真实回复。未回复只能写“待验证”。

私密 JSON 配置包含 `stateFile`、`hostLog`、`issueId`、`executor`、`scenario`、`tokenEnv`、`workspace`、`receiptFile`、`project`；peer 场景另需 `childIssueId`、`peerMarker`。项目 id 以 `acceptance-` 开头。凭据只注入协调者及 host 环境，所有真实配置、ID、路径、回执和 transcript 留在忽略目录或私密运行目录。

```sh
node scripts/native-acceptance.js --execute /private/acceptance-config.json
```

记录实际时间、执行器、同会话轮数、回写读回、负向对照与配置恢复情况。不要把脚本退出 0 当成任意业务成功。生产任务仍需业务正式验收。
